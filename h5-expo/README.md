# 小程序 A · 展会预登记（H5 mobile）

第34届北京国际美博会的观众预登记入口。设计稿来源：Claude Design 项目
`美博会AI社群Demo.dc.html`（丽人公社双小程序方案）中 **小程序 A** 的 4 屏。

> 双小程序拆分的原因：展会流量入口保持在主办方自己的品牌下，社群/AI 能力放在
> 另一个小程序里，两边靠一次跳转连起来，前台不混在一起。
> 配套的社群小程序在 [`../h5-liren`](../h5-liren)。

| | |
| --- | --- |
| 展会预登记 | https://www.aibuzz.cn/expo/ |

| 带演示话术 | https://www.aibuzz.cn/expo/?script=1 |

重新发布（只同步文件，不动 nginx）：

```bash
bash scripts/deploy-h5.sh
```

部署细节：文件放在测试机 `/opt/h5demo/{expo,liren}`，由 `aibuzz-ssl.conf` 里新增的两个
`location` 直接做静态服务（`root /opt/h5demo`），没有反代、没有后端。改配置前备份在
`/root/nginx-backup-aibuzz-ssl.conf.<时间戳>`，回滚就是把它拷回去再 `nginx -s reload`。

## 本地跑起来

需要用 HTTP 打开（`file://` 下 localStorage 在部分浏览器不可用）：

```bash
python3 -m http.server 8765 --directory /Users/donis/dev/ai-business
```

然后浏览器开 `http://localhost:8765/h5-expo/`，切到手机视图（iPhone 390×844 最贴设计稿）。

真机演示：手机与电脑同一 Wi-Fi，把 `localhost` 换成电脑内网 IP 即可。

**演示话术模式**：URL 加 `?script=1`，顶栏右上角出现一个「话」按钮，点开是当前这一屏
的讲法与对应的会议纪要原话。不加参数时页面是干净的产品界面，可以直接给客户看。

```
http://localhost:8765/h5-expo/?script=1
```

话术弹层底部有「重置演示数据」，清掉登记、报名、会员等级，换一位客户重新演一遍。

## 10 屏 · 四种身份

| 路由 | 屏 | 身份 | 说明 |
| --- | --- | --- | --- |
| `#/home` | 展会首页 | 观众 | 沉浸式头图 + 展期信息 + 预登记三项权益 + 分身份工作台入口 |
| `#/register` | 观众预登记 | 观众 | 真实表单（姓名 / 手机号 / 企业 / 身份类别）+ 关注品类多选 |
| `#/pass` | 电子入场证 | 观众 | 登记成功页，二维码 + 证件信息 + 跳转社群小程序 |
| `#/calendar` | 活动日历 | 观众 | 多期多城活动（大展 / 论坛 / 闭门会 / 城市站 / 线上）+ 城市筛选 |
| `#/forum` | 同期论坛 | 观众 | 分类筛选 + 主论坛 / 闭门会 / 待开放三种席位状态 |
| `#/exhibitor` | 参展商工作台 | 参展商 | 展位卡 + 一展商一码 + 邀客漏斗 + 增值服务商城 + AI 海报 / 口播脚本 / 嘉宾视频 |
| `#/staff` | 工作人员工作台 | 工作人员 | 每日任务打卡 + 四套可复制文案 + 邀约龙虎榜 |
| `#/organizer` | 主办方看板 | 负责人 | 今日到账 KPI + 增值订单流水 + 渠道排行 + 自动分账与提现 |
| `#/checkin` | 现场核销 · 预演 | 工作人员 | 手机扫码核销 + 重复扫码拦截 + 到场提醒展商 + 手工补签 |

四个工作台从首页「分身份工作台」区进入；核销台从主办方看板或欢迎屏进入。

## 能点的地方（都是真的）

- 表单是真实输入，手机号只收数字并限 11 位；三项必填齐了按钮才从
  **「一键带入微信资料」**（一键填演示数据）变成 **「提交登记」**。
- 关注品类多选，默认勾选「体重管理 / 产后修复」，会写进入场证下方的军师建档文案。
- 提交后按手机号后 6 位生成入场证编号（`BBE34-2026-xxxxxx`），刷新不丢。
- 同期论坛：未登记时点报名会先提示去预登记；闭门会报名后席位从 `9 / 30` 变
  `8 / 30 · 审核中`，按钮变「审核中」。
- 入场证底部「进入丽人公社」跳到 `../h5-liren/`，两边同源共用 `localStorage`，
  姓名 / 企业会带过去。
- **参展商工作台**：「生成今日邀客海报」弹出 AI 海报预览（品牌 + 展位 + 二维码），
  可切朋友圈 3:4 / 易拉宝 9:16 / 横屏 16:9 三种规格、换一版文案、复制文案；
  增值服务（399 / 1,000 / 2,000）点「开通」即生效并写入 localStorage，
  开通「客户跟踪」后受邀客户区角标变为「到场提醒 已开通」。
- **主办方看板**：今日到账、订单流水、渠道排行、70/20/10 自动分账、
  可提现余额与「申请提现」（toast 演示）。
- **现场核销**：点「扫码核验」跑 0.9 秒识别动画后核销成功
  （已登记则显示真实登记人，否则用演示客户），并 toast「已通知展商 E12」；
  同一证第二次扫会弹「重复扫码」拦截卡，显示首次入场时间；支持手工补签弹层。
- **展商新工具**：「30 秒口播脚本」按 0–5s / 5–15s / 15–25s / 25–30s 分镜给提词，
  一键复制到提词器；「嘉宾祝贺视频 · 拍同款」三档按次授权，
  未签授权的明星档位置灰且不可点——授权台账的产品化表达。
- **活动日历**：城市 pill 实时筛选，空城市显示空态；「待开放」场次点了提示未开放。
- **工作人员工作台**：任务打勾即时更新「x / 4 已完成」并写入 localStorage；
  四套文案（朋友圈官宣 / 干货 / 一对一邀约 / 视频号口播）一键复制；
  龙虎榜里「我」这一行高亮为品牌色。
- **现场欢迎屏**：每 3.2 秒换一位到场客户，入场数同步翻牌（`prefers-reduced-motion`
  下静止显示首位）；离开页面自动停止计时器。

## 数据与合规

- 纯静态：**没有后端、没有一个网络请求**，所有状态写在本机 `localStorage`
  （键前缀 `lrgs:`，与小程序 B 共用）。展会现场断网也能演。
- 入场证二维码 `assets/qr.svg` 是设计稿里的示意图形，**不是可扫描的真码**，
  真实入场码需要接组委会的核验系统。
- 同期论坛日程、席位数为演示排布；官方标注为「拟定」，以正式邀请函为准。

## 图片资产

- `hero-expo.jpg` 与三张 `forum-*.jpg` 由 codex CLI 的 `imagegen` skill 生成，
  统一约束：暖棕 / 深褐 / 米金色调、真实摄影质感、**画面内不出现任何文字与清晰人脸**、
  左下留干净暗部给标题压字。要换风格就重跑一次生成，替换同名文件即可。
- 底部 tab 图标是手写的内联 SVG（在 `js/app.js` 的 `ICONS` 里），跟随 `currentColor`
  变色，选中态加粗描边——图标类的东西用矢量比用生成位图清楚得多。
- `icon-180/512.png` 是用系统宋体渲染的「美」字图标，脚本化生成，不是 AI 图。

## 演示话术（对应设计稿右栏）

**`#/home` 流量入口不变，还是您的展会**
- 首页就是第34届北京美博会的预登记页，品牌、标识、主承办署名全是您的体系，我们不出现在前台。
- 观众来源不变：朋友圈、老客群、渠道邀约、现场扫码，四条路径都汇到这一页。
- 这一步我们不碰您的流量归属，只是把纸质登记换成一次可沉淀的数字动作。
- 纪要：「如果说你是博览会主席，你愿意把你的流量全变成我们合资公司的吗？那这个其实是不大对的。」

**`#/register` 登记表单就是第一次画像**
- 字段按官方观众类别设计：品牌商、代理商、美容院、门店、供应链、电商。
- 关注品类勾选就是后面 AI 军师推荐展商、推荐论坛的依据，用户不觉得在填资料。
- 这一屏是整个数据资产的起点——线索归属写在合同里，数据留在您这边。
- 纪要：「他不要进去的时候要登记注册报名，产生一个二维码。」

**`#/pass` 二维码是入场证，也是入群钥匙**
- 扫码入场是他原本就有的刚需，我们只是把它做得更体面。
- 入场证下面挂一句「AI 军师已为您建档」，这是第一次让观众感知到 AI，成本为零。
- 底部按钮把人导进社群小程序——两个小程序，跳转一下，前台不混在一起。
- 纪要：「最好的方式是什么？是直接给他们做两个小程序。」

**`#/forum` 同期论坛就是闭门会报名入口**
- 2026 减肥产业大会、抗衰老论坛、中医健康与美容论坛，全部挂在这里报名。
- 闭门会限席位、需审核，天然筛出品牌老板这一层人——不需要一次拉一百人。
- 报名记录直接进社群档案，谁来过哪场会，军师都知道。
- 纪要：「无非就是线下的会议有一个报名入口。」

**`#/exhibitor` 参展商是第二个付费方**
- 参展商报名审核通过，自动获得工作台：一展商一码，邀了谁、谁打开、谁登记、谁到场全程可见。
- 增值服务像商城一样陈列：客户跟踪 399、AI 物料 1000、媒体直播 2000，想用就开通。
- 126 家参展商每家买一两个增值包，就是主办方在展位费之外的新收入。
- 纪要：「如果我作为商场商来说，我是想买这样的服务的。」

**`#/organizer` 主办方只看三件事：到账、渠道、分账**
- 每一笔增值服务到账实时进列表——会上说的「叮叮叮」的体感。
- 渠道排行来自一人一码：朋友圈、工作人员、参展商、媒体，谁带来的登记一目了然。
- 钱在支付时按比例分好，各方看各自的可提现余额，不经过任何一方中转再结算。
- 纪要：「就是看到叮叮叮你有多少钱到账了，399的里面谁成交了？」

**`#/checkin` 一部手机就是核销闸机**
- 工作人员扫观众入场证，3 秒核销，不租闸机、不买设备、不用年度续费。
- 重复扫码提示首次入场时间；受邀客户一扫码，对应展商立刻收到到场提醒。
- 纪要：「你报名是报名，签到是签到嘛。我们是不是帮他省了设备的钱？」
